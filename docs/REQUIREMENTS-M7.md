# REQUIREMENTS-M7 — 桶管理（在管理页里自己建桶 / 看桶 / 删桶）

> 自包含需求书：不依赖对话上下文。冲突时以仓库现状为准，直接实现，不要提问、不要中断。

## 背景

objbox 的隔离模型是「账号 = 独立存储空间」，桶在该账号根目录下。此前用户只能靠客户端建桶或用命令行，
管理页里**没有桶的查看与管理入口**。本阶段把桶做成管理页里的一等公民：能看到、能自己建、能删、
能看到占用，并且知道哪个是账号的默认桶。

> M5 已实现「建号即建桶 / 请求即建桶」，M6 已实现「账号详情窗口 + 一键复制接入信息」。
> 本阶段在此之上补齐**桶管理**，三者合起来才是完整功能。

## 1. 后端 API（挂在 `/api/admin/accounts/{name}/` 下，鉴权与错误体形状沿用现有管理 API）

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/admin/accounts/{name}/buckets` | 返回该账号的桶数组：`[{name, objects, bytes, isDefault}]`。`objects/bytes` 走现有 `internal/usage` 统计；`isDefault` 标记该账号 `bucket` 字段指向的桶 |
| POST | `/api/admin/accounts/{name}/buckets` | body `{name}`；建桶。桶名走现有 `ValidateBucket`（**不得放宽**）。已存在 → `409` + 明确中文错误；成功 → `201` |
| DELETE | `/api/admin/accounts/{name}/buckets/{bucket}` | 删**空**桶；非空 → `409` + 明确错误（提示桶内还有对象）；不存在 → `404`。删除默认桶时若 `autoCreateBucket=true`，允许删除但**不得**自动重建（重建只发生在数据面请求时，见 M5） |
| PATCH | `/api/admin/accounts/{name}/bucket` | body `{bucket?, autoCreateBucket?}`；改该账号的默认桶名与自动建桶开关；桶名非法 → `400` |

- 路径/方法/鉴权/错误体形状与现有 `/api/admin/accounts*` 完全一致；**任何响应都不得包含 SK 明文**（除既有 reveal 接口）。
- 审计动作：`accounts.bucket.create` / `accounts.bucket.delete` / `accounts.bucket.update`，记录账号名与桶名。
- 账号不存在 → `404`；管理面未认证 → 现有一致行为（`401`）。
- 变更账号的 `bucket`/`autoCreateBucket` 必须**原子写盘**（沿用现有 0600 原子写），且不破坏热重载。

## 2. 前端（`web/`）

- 账号列表每行新增「桶管理」入口 → 面板/窗口，内容：
  - 桶列表：桶名、对象数、占用体积、默认桶标记；
  - 新建桶：输入框 + 按钮（就地校验桶名规则，非法给明确中文提示；已存在给明确提示）；
  - 删除桶：二次确认（说明"仅空桶可删，桶内还有对象时需先清空"）；
  - 默认桶与「自动创建同名桶」开关：可就地修改并保存；
  - 每行桶名可一键复制。
- 账号详情窗口（M6）里的桶区块与「桶管理」**共用同一组件**，不要两份实现。
- 新建账号表单里的桶名输入与 M5 的实现保持一致（同一套校验提示）。
- 样式沿用现有页面（直角、发丝线、单琥珀点缀）；**不新增依赖、不引图标库、不用 emoji**；中文克制文案，
  不写技术说明性文案；错误提示用后端返回的明确消息。
- 前端构建产物仍走 `//go:embed all:dist`；`make build` 顺序保持「先构建前端再 `go build`」。

## 4. 测试与自检

- 单测/集成（沿用现有脚手架，真 SigV4 签名）：
  1. GET 返回桶列表与 `isDefault` 标记正确；
  2. POST 建桶成功、重名 409、非法名 400、未认证 401、未知账号 404；
  3. DELETE 空桶成功、非空桶 409、不存在 404；
  4. PATCH 改默认桶/开关后落盘可重读（热重载读回新值）；
  5. 任何管理接口响应都不含 SK 明文（断言字符串不出现 SK）。
- 自检：`go vet ./...` 0 报错；`go test ./... -count=1 -race` 全绿；`make build` 成功；前端构建通过。
- 隐私自检：仓库内不得出现真实域名、公网 IP、密钥、邮箱（示例一律 `s3.example.com` / `127.0.0.1`）。
