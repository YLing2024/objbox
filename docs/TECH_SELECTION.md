# objbox 技术选型（v1 · 待你确认）

> 本文只做**选型**，不含实施。所有结论都有事实来源：仓库数据 = GitHub API 实时取（2026-10-07）；
> 代码事实 = 实际读过源码（gofakes3 已在本地 clone 通读，未运行任何服务）。

## 0. 需求约束（选型的尺子）

1. 概念少：**只有 admin + 账号**，无注册/无登录页/无用户表
2. 每账号一套 **AK/SK**，账号之间**硬隔离**
3. **无中间件**（不要 PG/Redis），单二进制/单容器优先，空闲占用接近 0
4. 协议行为要对得上真实 S3 客户端（`aws s3`、`rclone` 直接用）
5. 运维负担接近零：能"停掉不伤心"

## 1. 路线选型（最重要的一条）

| 路线 | 候选 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| ① 直接用现成服务 | MinIO（★61.3k / AGPL-3.0 / Go / 2026-04）· RustFS（★34.5k / Apache-2.0 / Rust / 2026-10）· SeaweedFS（Apache-2.0 / Go）· Garage（Apache-2.0 / Rust，自有 Git 托管）· cloudserver（★1.95k / Apache-2.0 / JS）· Ozone（Apache-2.0 / Java）· Swift（Apache-2.0 / Python） | 协议完整、久经生产 | **全是"平台体量"**：集群/多节点/控制台/用户与策略体系 ✗；我们要的只是"几套 AK/SK + 目录隔离"这一薄层 ✗；MinIO 社区版持续瘦身 ✗ | **否** ✗ |
| ② 现成 S3 网关包一层 | **versitygw**（★2.99k / Apache-2.0 / Go / 129 open issues） | 协议实现最全、有 POSIX 后端 | 它自带上 **用户/角色/策略（IAM）体系** ✗ —— 与"无用户系统"正好相反，砍它的 IAM 比自己写更费 ✗ | **否** ✗ |
| ③ **复用协议层库 + 自研隔离层** | **gofakes3**（★938 / MIT / Go / 37 文件 9211 行 / Go 1.24） | 与 davbox 同一哲学（"协议层不重写"）；路由、XML 编解码、列表、**分片全流程**、错误 XML 都已实现；隔离层是我们唯一的增量 | **它不做签名校验**（我通读源码确认：全文没有 SigV4/hmac/signingKey）→ 认证必须自己接 ✗；且 Backend 接口签名里**不带调用者身份** → 能否按账号切后端需先验证 ✗ | **首选，但要过验证门槛**（见 §4） |
| ④ 全自研协议层 | 手写路由 + XML + SigV4 | 完全可控、零协议依赖 | 手写 SigV4 是**最容易埋安全洞**的地方（规范化、编码、时间容差）✗；S3 客户端的边界行为很多 ✗ | **备选**（当 ③ 验证不通过时） |

**一句话结论**：不重写协议是原则，但 S3 生态的 Go 侧**没有"自带认证的可用协议库"** ✗ —— 所以 objbox 的自研增量锁定在两件事：**认证（AK/SK → 账号身份）+ 隔离（账号根目录白名单）**，其余交给协议层。

## 2. 逐层选型

| 层 | 候选 | **选择** | 理由 |
|---|---|---|---|
| 语言 | Go / Rust / Node | **Go 1.26** | 与 davbox 同栈、单二进制、交叉编译；Rust 维护成本 ✗、Node 单二进制部署弱 ✗ |
| 自动化构建 | Makefile / Taskfile | **Makefile** | 同 davbox（`frontend` → `go build`） |
| HTTP/路由 | 标准库 net/http / chi / gin / echo | **标准库**（S3 路由形态特殊：桶名在路径首位，框架帮不上） | 少一个依赖 |
| 协议层 | gofakes3 / versitygw / 自研 | **gofakes3（过验证门槛后）** | §1 路线 ③ |
| **签名校验** | ① 复用 `aws-sdk-go-v2/aws/signer/v4` **重算比对** ② 手写 HMAC 链 | **①** | **不自研密码学**；只用 SDK 的算法实现来做"重算并对齐 Authorization 头" |
| 元数据索引 | 纯文件系统 + sidecar JSON / **bbolt** / SQLite / 内存索引 | **bbolt（★9.8k / MIT / Go / 2026-09）** | 单文件、纯 Go、事务、无独立进程 ✓；sidecar 的代价是"双写一致性 + 列表要遍历目录" ✗；索引可随时按数据目录**重建** ✓ |
| 对象存储 | 直接落盘 / **哈希分片目录** | **哈希分片**（`<sha256 前2>/<次2>/<原名>`） | 避免单目录几十万条目拖死 ext4 ✗ |
| 配置 | JSON / TOML / YAML / 环境变量 | **JSON（0600）+ 环境变量覆盖** | 同 davbox 的 `accounts.json`，概念延续 ✓ |
| CLI | 标准库 flag / cobra | **标准库 flag** | 子命令少，不引依赖 |
| 管理页前端 | React+Vite+TS / 原生 / Svelte | **React 19 + Vite + TS，产物 `//go:embed`** | 与 davbox（`web/embed.go`）、homepage 同栈 ✓ |
| 管理端认证 | 自带口令 / SSO | **`AUTH_MODE=builtin`（默认）/ `sso`（Auth Gateway）** | 沿用 davbox 铁律：**协议端点永远 AK/SK，不受 AUTH_MODE 影响** ✓ |
| 部署 | systemd 单二进制 / Docker / K8s | **systemd 单二进制 + 可选 Docker** | 轻 ✓；K8s ✗ |
| 端口/数据/域名 | — | **127.0.0.1:18930**（已确认空闲）/ `/data/objbox`（ext4，剩 40G）/ `s3.s3.example.com` | 与 davbox（18900）并列 |

## 3. 明确否决清单（写在前面，避免中途长歪）

- ✗ 集群 / 多节点 / 纠删码 / 副本编排
- ✗ 用户注册、登录页、OAuth、STS 临时凭证
- ✗ ACL / Bucket Policy 引擎 —— 权限只保留**账号级 `readonly`** 一个开关
- ✗ 版本控制、对象锁、生命周期、事件通知、跨区复制、S3 Select、静态网站托管
- ✗ 匿名公开桶（要分享就用**预签名 URL**，用完即失效）
- ✗ 服务端加密（SSE）—— 靠磁盘层面，不做协议层

---

## 4. 唯一需要先验证的技术门槛（实施第一步，0.5 天）

**要验证的三个问题**（只读源码 + 最小可跑验证，不部署任何现成服务）：

1. gofakes3 能否**按请求拿到调用者身份** → 决定"按账号切隔离后端"能否干净实现
   - 能 → 采用路线 ③
   - 不能（Backend 接口不带 ctx/身份）→ 改成：**认证前置中间件 + 每账号一个 Backend 视图**，或退到路线 ④
2. 分片上传在当前版本是否完整（源码里 `CreateMultipartUpload/ListParts/Complete/Abort` 都在 ✓，但可用性要真跑一遍）
3. 预签名 URL（`X-Amz-Signature` 查询串）是否被协议层正确处理（若不带，认证层自己兜 ✓）

**门槛不通过就转路线 ④** —— 即：自研路由与 XML，仅用 `aws-sdk-go-v2` 的 signer 做校验，代码量预估 +1~1.5k 行。
