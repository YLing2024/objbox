# 关键取舍（Decisions）

记录本项目有意为之、且容易被后续改动破坏的设计决定。改动前请先读这里。

## 1. 403 统一语义

**决定**：无此 AK、账号停用、跨账号访问、只读账号的写操作、预签名过期，一律返回
`403 AccessDenied`，且响应体逐字节一致（认证层不注入随机字段，request-id 只出现在响应头）。

**原因**：如果"跨账号"和"桶不存在"能通过状态码或报文区分，就等于提供了一个枚举账号与对象的
信道。逐字节一致让攻击者无法据此探测。这也是为什么认证/预检错误直接写原始 writer，
而不是经过会附加字段的响应包装。

## 2. SK 明文落盘

**决定**：`accounts.json` 以明文保存 SK（文件权限 0600），不存哈希。

**原因**：SigV4 校验要求服务端重算 HMAC 链，必须拿到与客户端一致的明文 SK；只存哈希无法完成
重算。因此安全性依赖文件权限与部署环境，而不是"加密存储"。轮换 SK 会使旧 SK 立即失效；
管理页默认掩码 SK，只有显式 `?reveal=<name>` 且已鉴权才返回明文。

## 3. bbolt 索引可重建

**决定**：对象内容直接落盘，元数据存 `<root>/.objbox/meta.db`（bbolt）；启动时以磁盘为准重建索引。

**原因**：文件才是唯一事实来源。即使 `meta.db` 丢失或损坏，只要对象文件还在，就能通过重算
MD5 恢复 ETag/大小等元数据；元数据存在但文件已消失的条目会被删除。这让"把对象文件拷进来"
这种手工操作也能被正确纳管，代价是启动时可能重算哈希。

## 4. 只读账号与"以磁盘为准"的桶发现

**决定**：桶的存在性以账号 root 下的目录为准（`ListBuckets` 直接读目录）；只读账号拒绝一切写
操作，但读取不受影响。

**原因**：与第 3 条一致，磁盘是事实来源。手工创建/删除桶目录也能被正确反映，不依赖额外的
桶注册表。只读是账号级开关，在认证后的预检阶段拦截写方法，不进入协议层，避免半途失败。

## 5. 管理会话的服务端失效

**决定**：会话令牌是无状态签名 `base64(user|expiry|epoch).HMAC`；`<data>/admin.json` 维护
`sessionEpoch`，登录时写入签发值，校验时要求相等，`logout` 时递增并原子落盘。

**原因**：纯无状态签名无法主动失效，登出后旧 cookie 在有效期内仍可通过校验。单管理员场景下
"登出即提升 epoch、使全部会话失效"是简单且可接受的做法，也顺带覆盖了"改口令后旧会话仍有效"
的问题。

## 6. AUTH_MODE 注入的占位符

**决定**：前端读取 `window.__OBJBOX_AUTH_MODE__`；服务端把 `__OBJBOX_AUTH_MODE_VALUE__`
替换为模式值。

**原因**：若用 `__OBJBOX_AUTH_MODE__` 本身作为值占位符并整体替换，变量名里的同名子串也会被替换，
产出 `window.builtin = 'builtin'`，导致前端永远读不到模式。变量名与值占位符必须不同名。
